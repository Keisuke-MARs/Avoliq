# Avoliq カードタイトルの可読性 設計書

作成日: 2026-08-25
ステータス: ユーザー承認済み（ブレインストーミングセッションにて承認）
対象Issue: [#3 カードのタイトルが1行で切れて読めない（盤面の幅と表示行数）](https://github.com/Keisuke-MARs/Avoliq/issues/3)

既存の `2026-08-20-avoliq-palette-design.md`（設計書）と
`2026-08-20-implementation-contract.md`（実装コントラクト）を前提とする。

## 問題の実測

現状（ウィンドウ幅720px・既定のステータス4レーン）でタイトルに使える幅は次のとおり。

| 段 | 計算 | 幅 |
|---|---|---|
| ボードの内側 | `720 − 24`（`Board` の `px-3`） | 696px |
| 1レーン | `(696 − 36) ÷ 4`（`gap-3` × 3本を差し引いて4等分） | 165px |
| カードの内側 | `165 − 24`（`TaskCard` の `px-3`） | 141px |
| タイトル | `141 − 14`（ステータスドット6px + `gap-2` 8px） | **127px** |

13pxフォントの日本語は1文字あたり約13pxなので、**表示できるのは約9〜10文字**。
`TaskCard.tsx` のタイトルが `truncate`（1行・省略記号）であるため、
ここを超えたタイトルはすべて `…` になり、タスクを判別できない。

## 決定事項サマリ

| 項目 | 決定 |
|---|---|
| ウィンドウ幅 | 720px → **880px**（高さ480pxは据え置き） |
| タイトルの行数 | `truncate` → **`line-clamp-2`**（最大2行） |
| レーンの最小幅 | `min-w-0` → **`min-w-[160px]`** |
| レーンがはみ出したとき | ボードを**横スクロール**（`overflow-x-auto`） |
| 選択カードの追従 | `scrollIntoView` に **`inline: "nearest"`** を追加 |
| 並び替え時の追従 | `useEffect` の依存に **`task.statusId` / `task.position`** を追加（レビューで判明した既存バグ） |
| スコープ外 | 詳細ビューの読み幅（`max-width`）、ウィンドウ高さの変更、レーン数の上限、LPスクリーンショットの撮り直し |

変更後、4レーン時のタイトル幅は `(880 − 24 − 36) ÷ 4 = 205px` → `205 − 24 − 14 = 167px`。
2行で**約25文字**となり、現状の約2.6倍になる。

### 却下した代替案

- **ウィンドウ幅の拡大のみ（880px・1行のまま）**:
  タイトル幅は127px → 167px、文字数にして9文字 → 12文字にしかならない。
  Issueの「何のタスクなのか判別できない」はほぼ解消しないまま、
  ウィンドウだけが2割太る。費用対効果が最も悪いため却下。
- **`line-clamp-2` のみ（720px維持）**:
  2行で約19文字。判別できる下限には達するが、
  幅を足せば同じ2行でさらに6文字稼げる以上、あえて狭いまま据え置く理由がない。
  なお本案の「19文字」という水準は、レーン最小幅160pxの根拠として採用している（後述）。
- **レーン数に応じてウィンドウ幅を可変にする案**:
  横スクロールを出さずに済む唯一の案だが、ステータスの増減のたびに
  Tauriのウィンドウリサイズを呼ぶ必要があり、`resizable: false` の
  固定ウィンドウという前提と、中央固定で現れるパレットの挙動を壊す。
  得られるものに対して仕組みが重すぎるため却下。
- **レーン数を等分のまま据え置く案（現状維持）**:
  `flex-1 min-w-0` は下限なく縮むため、6レーンで約136px、8レーンで約95pxになる。
  2行表示にしても2〜3文字で折り返して実質読めない。Issueの
  「レーン数を増やしても表示が崩れない」を満たさないため却下。

## 変更内容

### 1. ウィンドウ幅（`src-tauri/tauri.conf.json`）

`app.windows[0].width` を `720` → `880` にする。それ以外は変更しない。

**高さ480pxを据え置く理由**: Spotlight風パレットの「軽さ」は主に縦の占有量で
決まる。横に広げても画面下端との距離は変わらないが、縦に伸ばすと
「一時的に呼び出す小窓」から「常駐アプリのウィンドウ」に印象が変わる。
880pxはMacBook 13インチ（1440px幅相当）の約61%で、
画面を覆い尽くさない範囲に収まる。

### 2. タイトルを2行まで表示（`src/components/TaskCard.tsx`）

タイトルを包む span:

```
- <span className="min-w-0 truncate">{task.title}</span>
+ <span className="min-w-0 break-words line-clamp-2">{task.title}</span>
```

`break-words` を併記するのは、`truncate` が内包していた `whitespace-nowrap` が
外れることで、URLのような切れ目のない文字列がタイトルのときに
`line-clamp-2` だけでは横にはみ出すため。日本語は任意の位置で折り返せるので
問題にならないが、英語・URLのタイトルで崩れる。

タイトル行のレイアウト:

```
- <div className="flex items-center gap-2">
-   <span className="av-status-dot h-1.5 w-1.5 shrink-0 rounded-full" />
+ <div className="flex items-start gap-2">
+   <span className="av-status-dot mt-[6px] h-1.5 w-1.5 shrink-0 rounded-full" />
```

`items-center` のままだと、2行になったときステータスドットが
カード高さの上下中央（＝1行目と2行目の境目）に来て1行目とずれる。
`items-start` で上寄せにしたうえで、ドットを1行目の中心に固定する。

`mt-[6px]` の根拠: 1行の高さは `13px × leading-snug(1.375) ≈ 17.875px`。
ドットは6pxなので、1行目の中心に置くには `(17.875 − 6) ÷ 2 ≈ 5.94px` → **6px**。

### 3. レーンの最小幅（`src/components/Lane.tsx`）

```
- className="flex flex-1 min-w-0 flex-col"
+ className="flex flex-1 min-w-[160px] flex-col"
```

`min-w-0` は「コンテンツ幅より小さく縮めてよい」ことを示すために置かれていた。
`min-w-[160px]` も同じ役割を果たしつつ、縮む下限を与える。

**160pxの根拠**: 880px幅では、5レーンまでは各161.4px
（`(879 − 24 − 12×4) ÷ 5`。`gap-3` が12px、5レーンなら隙間は4本）となり、
160pxを下回らないため横スクロールが出ない。
`160×5 + 48 + 24 = 872 ≤ 879` が成立する最大の丸い値が160px。

分母が880ではなく**879**なのは、`Palette` の `w-screen`（880px）から
`.av-glass` のボーダー `0.5px` × 左右を引いた内側の幅だから（`box-sizing: border-box`）。
つまり5レーン時の余裕は8pxではなく**7px**しかない。
ボーダー幅・`gap-3`・`px-3` のいずれかを変えるときは、この式を計算し直すこと。
6レーン以降は各160pxを保ったまま横スクロールに移行する。
160pxのときタイトル幅は `160 − 24 − 14 = 122px` で、2行なら**約19文字**。
これは「`line-clamp-2` のみ（720px維持）」案と同じ水準であり、
判別可能と判断した下限にあたる。

### 4. ボードの横スクロール（`src/components/Board.tsx`）

```
- className="flex flex-1 gap-3 overflow-hidden px-3 py-3"
+ className="flex flex-1 gap-3 overflow-x-auto overflow-y-hidden px-3 py-3"
```

縦は各レーンの内側（`Lane` の `overflow-y-auto`）が持つため、
ボード自体の縦あふれは引き続き隠す。

### 5. 選択カードの横方向の追従（`src/components/TaskCard.tsx`）

```
- if (selected) ref.current?.scrollIntoView({ block: "nearest" });
+ if (selected) ref.current?.scrollIntoView({ block: "nearest", inline: "nearest" });
```

横スクロールを導入すると、`⌘←` `⌘→` でステータスを変更したとき
移動先のレーンが表示範囲の外にありうる。`block` は縦方向しか見ないため、
`inline: "nearest"` を足さないと選択カードが画面外に取り残される。
`"nearest"` なので、既に見えている場合はスクロールしない。

### 6. 選択されたまま位置だけ変わる操作への追従（`src/components/TaskCard.tsx`）

上記の `useEffect` の依存配列を `[selected]` から
`[selected, task.statusId, task.position]` に広げる。

これはコードレビューで見つかった**既存のバグ**で、今回の変更が原因ではないが、
2行表示でカード高さが増える（レーンあたりの可視枚数が減る）ぶん踏みやすくなるため、
同じ変更に含めて直す。

- `⌘←` `⌘→`（`moveSelectedTask`）は `statusId` を変えるため、カードが別のレーン＝
  別の親要素へ移り、React が再マウントする。マウント時に effect が走るので追従していた。
- `⌘↑` `⌘↓`（`reorderSelectedTask`）は `position` しか変えない。`Lane` は
  `key={task.id}` でカードを並べているため、同じ親の中で並び替わるだけで
  **再マウントされない**。`selected` も `true` のままなので effect が再実行されず、
  選択カードがレーンのスクロール外へ出ても追従しなかった。

## 影響範囲（実装時に必ず踏むところ）

- **他のビューも880px幅になる**（詳細・ボード切替・ボード設定・アプリ設定）。
  詳細ビューは `px-8` / `mx-8` 固定のため、本文欄が656px → 816pxに広がる。
  656pxの時点で既に読み幅としては広く、今回の変更で生まれた問題ではなく
  既存の状態が強調されるだけなので、`max-width` の検討は本設計の範囲外とし、
  別Issueに切り出す。
- **`TagPalette` は `w-[300px]` 固定**なので幅の変化を受けない。
  中央寄せの位置だけが変わる。
- **`useChipOverflow` は実測ベース**（`row.clientWidth` と各チップの `offsetWidth`）
  だが、測り直しの引き金は `resetKey`（タグの `id:name` の連結）だけで、
  ResizeObserver は持たない。つまり**レーン幅の変化そのものでは測り直さない**。
  ただしステータスを増減すると `Palette.tsx` の `<div key={view}>` による
  ボード設定への往復で Board ごと再マウントされるため、実際には測り直される。
  タグ行は1行のままで、カード高さは「タイトル行数 + タグ行」の単純な加算になる。
- **カード高さの変化**: タグ無しカードは34px → 52px、タグ有りは52px → 70px
  （いずれも2行になった場合のみ）。`line-clamp-2` は短いタイトルを
  1行のままにするため、レーンに収まるカード数が減るのは
  長いタイトルのカードだけに限られる。レーンは元々 `overflow-y-auto` で
  スクロールするため、あふれても破綻しない。
- **ランディングページ（`landing/`）は一部が陳腐化する**。
  `PaletteMock` はウィンドウ寸法から寸法を導いておらず、独自のCSS変数
  （`--pm-card-h` など）で組まれているため影響を受けない。
  一方 `landing/public/shots/board.png` と `search.png`（ともに1600×1120）は
  **720×480のウィンドウから切り出した実写**なので、撮り直しが必要になる。
  放置すると、公開ページで「タイトルが1行で切れた盤面」＝今回直したバグを
  見せ続けることになる。撮り直すときは `landing/src/components/Shot.tsx` の
  `width={1600} height={1120}`（レイアウトシフト防止のための実寸）も
  比率が変わるなら合わせて更新すること。
  緊急度は低いため本設計の範囲外とし、別Issueに切り出す。
- **README**: ウィンドウ寸法への言及はないため更新不要。

## テスト方針

jsdomは `clientWidth` / `offsetWidth` が常に0で実寸を測れない
（`useChipOverflow` が明示的にこの前提で書かれている）。
したがって「何文字表示されるか」は自動テストで検証せず、
**クラスの有無と関数の呼び出し引数**を回帰テストとして固定する。

### React（Vitest + Testing Library）

`src/components/TaskCard.test.tsx` に追加:

- タイトルが `line-clamp-2` を持ち、`truncate` を持たないこと
  （回帰: `truncate` に戻すと1行に切れてIssue #3が再発する）
- タイトルが `break-words` を持つこと
  （回帰: 切れ目のないタイトルで横にはみ出す）
- 選択されたカードで `scrollIntoView` が
  `{ block: "nearest", inline: "nearest" }` で呼ばれること
  （回帰: `inline` が欠けると横スクロール時に選択カードが画面外に残る）

`src/components/Board.test.tsx` に追加:

- レーン要素（`data-testid="lane"`）が最小幅のクラスを持つこと
- ボード要素（`data-testid="board"`）が横スクロールのクラスを持つこと

### 手動スモークチェック

実ウィンドウでしか確認できないため、実装後に次を目視する。

1. 20文字程度のタイトルのタスクを作り、ボードで2行に折り返して読めること
2. 短いタイトルのカードが1行のままで、余計な高さを持たないこと
3. ステータスドットが1行目の中心に並んでいること（2行のカードでも）
4. ステータスを5つに増やして横スクロールが出ないこと
5. ステータスを6つに増やして横スクロールが出ること、
   かつ `⌘←` `⌘→` で選択カードが画面内に追従すること
6. タグ付きの長いタイトルのカードで、タグ行の「+n」表示が崩れないこと
