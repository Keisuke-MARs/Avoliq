# Avoliq ランディングページ 設計書

作成日: 2026-08-23

## 1. 目的とスコープ

Avoliq を **作品・実績として見せる** ための1ページ完結のランディングページを作る。

読み手は採用担当・面接官とエンジニアの両方を想定し、
**上に行くほど感覚で伝わる話、下に行くほど設計と技術の話** という並びにする。
Apple の製品ページと同じ構造を意図的に踏襲する。

### 成果物

`Avoliq/landing/` に独立した Vite + React + TypeScript プロジェクトを新設する。

### スコープ外

- ダウンロード提供（`.dmg` の配布）
- 日英切り替え
- 問い合わせフォーム、アナリティクス、フォーム送信を伴う機能
- 本体（`src/`, `src-tauri/`）への変更

### 前提

- リポジトリを public 化する前提で設計する（CTA が GitHub へのリンクになるため）。
  public 化の実行は本設計の範囲外で、別途承認を取る。
- 公開先は GitHub Pages を想定する。

### 公開順序の制約

**リポジトリを public にするまで、LP を公開してはいけない。**

LP の主 CTA は GitHub リポジトリへのリンクなので、private のまま LP だけ公開すると
訪問者には 404 が返る。また GitHub Pages 自体、private リポジトリからの公開には
Pro / Team プランが必要になる。

この前提があるため、**本文に「公開しています」のような公開状態を断言する記述を置かない**。
状態が変わったときに嘘になる文をコードに焼き込まないこと。
リンク先が読めることを前提にした案内（「リポジトリで確かめられます」）に留める。

## 2. 全体構成

10ブロックの縦一列。ルーティングは持たない。

| # | セクション | 主役 | 背景の役割 |
| --- | --- | --- | --- |
| 01 | Hero | 抽象パレットが開く | 最暗 |
| 02 | Statement | 思想を一文で | 暗 |
| 03 | Keyboard | パレットが前に出て操作実演 | 暗＋発光 |
| 04 | Feature 01 その場で検索、その場で作成 | 実スクリーンショット | 一段持ち上げ |
| 05 | Feature 02 ボードとタグで整える | 実スクリーンショット | 一段持ち上げ |
| 06 | Feature 03 すべてローカルで完結する | 大タイポ＋図 | 全幅の帯 |
| 07 | その他の機能 | 小カード6枚 | 暗 |
| 08 | Design Notes | 3つの設計判断 | 読み物サーフェス |
| 09 | Tech Specs | スタック表 | 読み物サーフェス |
| 10 | CTA / Footer | GitHub へのリンク | 最暗 |

### 絵柄の重複を避ける原則

抽象モックのパレットは **LP 全体で1つしか出さない**。

01〜03 は sticky ステージ上の同一の DOM 要素であり、スクロール進捗に応じて
「開く → 背景に退く → 前に出て実演する」と状態を変える。
04 以降には抽象パレットを一切登場させず、実スクリーンショットのみを使う。

これにより、抽象モックと実スクリーンショットで絵柄が完全に分かれ、
同じ絵を二度見せる状態が構造的に発生しない。

## 3. 各セクションの内容

### 01 Hero

- eyebrow: `for macOS`
- H1: `Avoliq`
- リード: 直感的に、自然に思考を整え、次へ進める。
- 本文: Alt + Space。画面の中央にパレットが開いて、キーボードだけでタスクが片づく。用が済んだら Esc で消える。
- CTA: 主「GitHub で見る」／副「設計を読む」（08 Design Notes へのアンカー）
- ビジュアル: 抽象パレット（検索欄＋3レーン＋カード5枚）

### 02 Statement

- 見出し: タスクを増やさない。迷いを減らす。
- 本文: 管理するために書くのではなく、次の一歩を選ぶために書く。だから Avoliq には、溜めるための機能がありません。開くのも閉じるのも一瞬で終わって、あとは目の前の作業に戻るだけです。

### 03 Keyboard（操作実演）

- ラベル: `Keyboard`
- 見出し: 手は、ホームポジションから離れない。
- 本文: 矢印で選び、⌘K でタグを付け、⌘→ で次のステータスへ。マウスに持ち替える瞬間が、そもそも要りません。
- ビジュアル: キーキャップ列（↓ / ↓ / ⌘K / ⌘→）が順に光り、
  パレット内で選択枠が移動 → タグチップが付く → カードがレーンを移動する

### 04 Feature 01 — その場で検索、その場で作成

検索欄に打った文字がそのままタスク名になり、`Enter` で新規作成される。
思考を止めずに書き留められることを主張する。実スクリーンショット。

### 05 Feature 02 — ボードとタグで整える

ステータス（レーン）ごとにカードを並べ、`⌘K` のタグパレットで付け外しする。
検索欄で `#タグ名` と打つと絞り込める（補完あり）。実スクリーンショット。

### 06 Feature 03 — すべてローカルで完結する

対応する画面が存在しないため、**スクリーンショットを使わない**。
大タイポ＋簡素な図（端末の中でデータが閉じている絵）による全幅の帯とし、
ここでページのリズムを一度変える。

- データは `~/Library/Application Support/Avoliq/avoliq.db` の SQLite ファイル1つ
- 外部への通信は一切行わない
- バックアップはそのファイルをコピーするだけ

### 07 その他の機能（小カード6枚）

1. Markdown 詳細エディタ（BlockNote、自動保存）
2. 複数ボードの切り替え（`⌘B`）
3. 削除の取り消し（ソフトデリート、`⌘Z` で元の位置に戻る）
4. メニューバー常駐／ログイン時自動起動
5. ライト・ダークの両対応
6. 画面下部に常時出るショートカットヒント

### 08 Design Notes（3つの設計判断）

それぞれ **課題 → 選んだもの → なぜ → 結果** の型で書く。

1. **ウィンドウの作法** — Tauri v2 ＋ `tauri-nspanel`。
   通常ウィンドウでは他アプリのフォーカスを奪い、Cmd+Tab の循環にも現れてしまう。
   NSPanel 化することで「呼んだらすぐ消える道具」としての振る舞いを実現した。
2. **データを閉じる** — Rust ＋ rusqlite によるローカル SQLite。
   同期やアカウントを持たない代わりに、外部通信ゼロとファイル1つのバックアップを得た。
3. **色を一元管理する** — 色の実値は `src/index.css` の `--av-*` にだけ置き、
   shadcn 変数も BlockNote 変数もそこを参照するだけにした。
   ライト・ダーク両方のコントラストを WCAG AA 基準で検証している。

## 5. モーション設計

イージングは本体と同じ `cubic-bezier(0.32, 0.72, 0, 1)` に統一する。

### 01〜03（sticky ステージ）

高さのあるトラック上に sticky なステージを置き、スクロール進捗 `p`（0→1）を
1つの `scroll` ハンドラで算出する。ハンドラは `requestAnimationFrame` で束ね、
`passive: true` で登録する。パレットの `transform` / `opacity` / `filter` と
テキストの表示を `p` から導出する。

**ステージ内の配置は CSS グリッドの3行で構造的に分ける。**

| 行 | 内容 |
| --- | --- |
| 1 | テキスト層（Hero / Statement / Keyboard の見出しを同じセルに重ねる） |
| 2 | パレット |
| 3 | キーキャップ層 |

テキスト層とパレットを `top-[14vh]` のような個別の数値で配置すると、
ビューポートの高さが変わるたびに関係が崩れ、低い画面では重なる。
実測では高さ 800px で約 92px 重なった。数値を詰めても別の高さで再発するだけなので、
**行を分けて重なりようがない構造にする**。行間は `gap-y-10`（40px）で、
これがどの画面サイズでも隙間の下限になる。

テキスト層の3セクションは同じセルに重ねてクロスフェードさせるため、
**不透明度が下がった層の当たり判定を消す必要がある**。
消さないと、見えていないセクションのリンクが押せてしまう。
`pointer-events` を CSS クラスの固定値にせず、不透明度に連動させる。

**行分けの保護は `transform` では破れる。**
`transform` はレイアウトの寸法を変えないので、`translate` を掛けた要素は隣の行へ食い込める。
実測では、パレットを `translateY(+70px)` で退避させたとき、縮小（`scale(0.7)`）で下端が
29px 戻るぶんを差し引いても 41px 下がり、40px の行間を 1px 超えた。

そのため **パレットの動きは `scale` / `opacity` / `blur` だけに限る**。
`scale` は 1 以下であれば中心へ縮むだけなので、自分のレイアウト枠から出ることがない。
このページのスケールは Hero=1.0 → Statement=0.7 → Keyboard=0.938 で最大が 1.0 なので、
**行分けの保護が破られない**。この不変条件はテストで固定する。

テキスト層の中での `translateY`（Hero と Statement）は、行をまたがないので問題ない。

この表は `landing/src/lib/motion.ts` の実装と1対1で対応する。
数値を変えるときは両方を必ず揃えること。

**登場演出（スクロールとは無関係）**

パレットが `blur(12px)` / `scale(0.92)` / `opacity 0` から鮮明・等倍・不透明へ開く演出は、
**ページに来た瞬間に一度だけ再生する CSS アニメーション**で行う。Spotlight は呼び出した瞬間に
開くものなので、スクロールを要求するのは挙動として誤り。
これをスクロールに紐づけると、**スクロール前の第一画面が何も見えない状態になる**。

パレット 850ms、Hero 700ms（120ms 遅延）。`prefers-reduced-motion: reduce` では無効化し、
最初から最終状態にする。

スクロール由来のスタイルはインラインで毎フレーム更新されるため、登場演出は**その外側の
ラッパー要素に掛ける**。同じ要素に両方を掛けると競合する。

**パレット（スクロール駆動。`p = 0` の時点ですでに開ききっている）**

| 区間 | 変数 | 挙動 |
| --- | --- | --- |
| `p` 0.16–0.30 | `back` | 縮小・減光して背景へ退く（`scale` ×0.70、`opacity` ×0.55、`y` +70px） |
| `p` 0.36–0.48 | `fore` | 拡大して前へ出る（`scale` ×1.34、減光が解ける、`y` −64px） |

**テキスト（不透明度と位置で終点をずらす）**

不透明度が先に落ち切り、位置だけ少し遅れて動き続ける。
動きが止まってから消えるのではなく、消えながら動き切ることで、切り替わりが滑らかになる。

| 対象 | 不透明度の区間 | 位置の区間 |
| --- | --- | --- |
| Hero | `p = 0` で表示済み。0.12–0.20 で消える | 0.12–0.22 で上へ 40px 抜ける |
| Statement | 0.17–0.24 で現れ、0.31–0.38 で消える | 0.17–0.26 で 20px 下から上がる |
| Keyboard | 0.37–0.44 で現れる | 位置の変化なし |

**操作実演**

| 区間 | 挙動 |
| --- | --- |
| `p` 0.50–0.92 | この区間を `demo`（0→1）に正規化し、以下を順に再生する |

`demo` の内訳。キーは `DEMO_KEY_COUNT`（4個）を `0.22` 刻みで、幅 `0.24` ずつ光らせる
（刻みより幅を広くとることで、境界にすき間ができない）。

| `demo` | 挙動 |
| --- | --- |
| 0.00–0.24 | 1つ目のキーが光る／選択枠が1枚目のカードに乗る |
| 0.22–0.46 | 2つ目のキーが光る／0.24 から選択枠が2枚目へ移る |
| 0.44–0.68 | 3つ目のキーが光る／0.46 から選択枠が3枚目へ移る |
| 0.52– | タグチップが付く |
| 0.66–0.90 | 4つ目のキーが光る |
| 0.74– | カードが隣のレーンへ移動する |

カードの移動は「上に重ねる」のではなく「**挿入する**」として見せる。
移動するカードが隣のレーンの1枚目のスロットに収まり、そのレーンの既存カードは
1枚分下へずれて場所を空ける。実際のアプリでもステータスを変えたカードは
そのレーンに入るので、重ねる表現は挙動として誤りになる。

移動量は概算を使わず、レーン幅（カード幅と一致する）とレーン間の隙間から厳密に算出する。

レーンのカード置き場には **カード3枚分の高さを常に確保する**。
`transform` はレイアウトの寸法を変えないため、高さを確保しないと、
既存カードが1枚分下がったときにパレットの枠を突き破ってしまう。
実際のカンバンボードもレーンの下に余白があるので、確保した余白は不自然に見えない。

### 04 以降

`IntersectionObserver` による一度きりのフェードアップ（`translateY(18px)` → `0`）。
一度発火したら `unobserve` する。

### アクセシビリティ

`prefers-reduced-motion: reduce` のときは **全アニメーションを無効化し、最終状態で静止させる**。
sticky ステージも通常フローの3セクションに落とす。
動きを切った状態でも情報が欠けないようにする。

## 6. 技術構成

| 項目 | 採用 |
| --- | --- |
| ビルド | Vite 7 |
| フレームワーク | React 19 + TypeScript |
| スタイル | Tailwind CSS v4（`@tailwindcss/vite`） |
| アニメーション | ライブラリなし（CSS ＋ 自前フック） |

アニメーションライブラリ（`motion` 等）を入れない理由は、
必要な動きが「スクロール進捗 → 数値」の一本道で、自前の小さなフックで足りるため。
依存を増やさない方が本体の方針とも揃う。

### ディレクトリ構成

```
landing/
  index.html
  package.json
  vite.config.ts
  tsconfig.json
  public/
    avoliq-logo.png
    shots/                  # スクリーンショット
  src/
    main.tsx
    App.tsx
    index.css               # 色トークン、ベーススタイル
    lib/
      motion.ts             # 進捗 → スタイル値の純粋関数群（テスト対象）
    hooks/
      useTrackProgress.ts   # sticky ステージの進捗 0→1
      useReveal.ts          # IntersectionObserver フェードアップ
      usePrefersReducedMotion.ts
    sections/
      Hero.tsx
      Statement.tsx
      KeyboardSection.tsx
      StickyStage.tsx       # 01〜03 を包む sticky コンテナ
      FeatureSearch.tsx
      FeatureBoard.tsx
      FeatureLocal.tsx
      FeatureGrid.tsx
      DesignNotes.tsx
      TechSpecs.tsx
      Footer.tsx
    components/
      PaletteMock.tsx       # 抽象パレット（LP 全体で1インスタンス）
      Keycap.tsx
      Shot.tsx              # スクリーンショットの枠と影
```

`StickyStage.tsx` が `useTrackProgress` の値を持ち、
`PaletteMock` と Hero / Statement / Keyboard のテキストへ配る。
各セクションコンポーネントは進捗値を受け取るだけで、スクロールを直接見ない。

### 本体プロジェクトとの分離

- `landing/` は独自の `package.json` を持ち、`npm install` も独立させる
- ルートの `package.json` / `vite.config.ts` / `tsconfig.json` は変更しない
- Tailwind v4 の `@source` がルートの `src/` を拾わないよう、`landing/src/index.css` の
  スキャン対象を `landing/` 配下に限定する

## 7. スクリーンショットの取得

`npm run tauri dev` で本体を起動して撮影する。デバッグビルドが残っているため増分ビルドで済む見込み。

### 注意点

- パレットは半透明で背後のデスクトップが写り込むため、無地の暗い背景を敷いて撮る
- LP がダーク基調なので、アプリもダークモードで撮る
- Retina 解像度で撮り、LP 側では 2x 表示にする

### 代替案

綺麗に撮れない場合は、実スクリーンショットを諦めて HTML/CSS で UI を再現する。
その場合は 01〜03 の抽象モックと絵柄が近づくため、
ウィンドウの枠・影・データ量で差をつけて重複を避ける。

## 8. メタ情報

- `<title>`: `Avoliq — 直感的に、自然に思考を整え、次へ進める。`
- `<meta name="description">`: macOS 向けの Spotlight 風タスクパレット。Alt + Space で開き、キーボードだけでタスクを片づける。データはすべてローカルに保存される。
- OGP / Twitter Card: ヒーローを 1200x630 で書き出した画像を `public/ogp.png` に置く
- favicon: `design/avoliq-app-icon.png` から生成する
- `<html lang="ja">`
- `color-scheme: dark` を指定し、ブラウザ UI もダークに揃える

## 10. 決定事項の記録

ブレインストーミングで確定した選択とその理由。

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| 置き場所 | リポジトリ内 `landing/` | ロゴと色トークンを流用でき、Pages で完結する |
| LP の目的 | 作品・実績として見せる | ─ |
