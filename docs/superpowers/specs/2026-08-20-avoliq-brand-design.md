# Avoliq ブランドデザイン設計書

作成日: 2026-08-20  
ステータス: ユーザー承認済み（完全改名の実装計画前）

## 1. ブランドの核

### 名前

- 正式名: **Avoliq**
- 読み: **アヴォリック**

`Avoliq` は辞書語ではない造語である。ブランド上は「思考を軽く整え、次の一歩へ進める」体験を表す。

### 約束

> 直感的に、自然に思考を整え、次へ進める。

タスクを増やして管理を強いるのではなく、迷いを減らし、目の前の一歩を選びやすくするmacOSアプリとして表現する。

### ブランドの人格

- 静かで、即応する
- 透明で、迷わせない
- 上質だが、見せびらかさない
- 前進を促すが、急かさない

## 2. シンボルマーク

### 意味

ガラスでできた青い一筆のチェックを採用する。これは単なる完了記号ではなく、捕まえた思考が次の行動へ自然に流れ出す軌跡を表す。

### 造形ルール

- マークは丸みのある正方形の中に置く
- チェックは太さを一定にした、一筆で読める形にする
- 半透明の尾、補助線、複数色のレーン、粒子、文字を追加しない
- 小サイズでも認識できるよう、余白を十分に取り、細部を増やさない
- ガラス感は白いハイライト、浅い屈折、控えめな内側の影で表現する

### 禁止事項

- `⌥`、`⌘`、`Space` など、操作キー・キーキャップ・ショートカット表記をロゴ、アイコン、LPの主ビジュアルに使わない
- 絵文字を使わない
- チェックと競合する装飾や、完了を過剰に祝う表現を使わない

## 3. カラーシステム

| 役割 | 名称 | 値 | 使い方 |
|---|---|---|---|
| アクション | Avoliq Blue | `#0A84FF` | チェック、主要CTA、選択状態 |
| 屈折光 | Glass Azure | `#66BEFF` | ガラス内部の淡い光のみ |
| 奥行き | Glass Violet | `#615EFF` | 背景のごく薄い屈折に限定 |
| 文字 | Ink | `#11213B` | 見出しと重要な文字 |
| 静かな本文 | Slate | `#52627A` | 本文と補助情報 |
| 背景 | Mist | `#F5F7FB` | LPと静的モックアップの背景 |
| ガラス | Frost | `rgba(255, 255, 255, 0.58)` | 最前面の一要素だけに使う |

青を唯一の行動色とし、紫は独立したアクセント色として使わない。Glass AzureとGlass Violetは、ガラスの屈折にだけ用いる。

## 4. Liquid Glass の使い方

AppleのLiquid Glassに倣い、ガラス素材はコンテンツより前面に浮く重要な一要素に限定する。

- アイコンでは、ガラスの屈折を固定した静的表現として使う
- アプリ実装では、可能な限りOS標準の素材と動作を優先する
- LPでは、ヒーローのシンボル、主要CTA、浮遊するカードのいずれか一箇所だけに留める
- ガラスを背景全面、本文カードの全数、または装飾目的で多用しない

### Avoliq アプリにおける適用

Avoliq のパレットはデスクトップの上に浮く単一の面であり、これ自体が「前面に浮く重要な一要素」にあたる。
したがって**パレットの器はガラスとして表現してよい**。
禁じるのはその内側での多用であり、タスクカード・ダイアログ・トースト・エディタのメニューにガラスを使わない。
ガラスの上にガラスを重ねると屈折が二乗になって濁るため、内側の浮きものはすべて不透明な面で置く。

ぼかしは `tauri.conf.json` の `windowEffects`（NSVisualEffectView）が担う。
透過ウィンドウでは CSS の `backdrop-filter` がデスクトップに届かないため、CSS だけでは実現できない。

実装仕様は `2026-08-21-avoliq-color-system-design.md` の5節を正とする。

## 5. タイポグラフィとLP展開

### 書体

- `-apple-system`, `BlinkMacSystemFont`, `"SF Pro Text"`, `"Hiragino Sans"`, sans-serif
- ロゴのワードマークはSF Pro系の中太ウェイトを基準に、字間をやや詰める

### コピーの調子

- 短く、具体的に書く
- 命令や煽りではなく、自然な変化を描写する
- 推奨コピー: `Move with clarity.` / `思考を整え、次へ進む。`
- 操作キーやショートカットの説明は、機能セクションにのみ置く。ヒーロー、ロゴ、アイコンのコピーには置かない

### LPの視覚要素

- 大きな余白と白に近いMist背景を基本にする
- Avoliq Blueを、主要な行動とマークだけに使う
- アプリの画面写真または静かな抽象光を使い、人物のストック写真や生産性を誇張するグラフは使わない
- カンバンのステータス色はプロダクトUI内でのみ使い、ブランドの主パレットへ持ち出さない

## 6. 完全改名の方針

`smartTask` を `Avoliq` へ完全に改名する。見た目だけを変える互換重視の改名にはせず、新しいアプリ識別子と保存先を持つ別アプリとして配布する。

### 変更する名称

| 区分 | 変更前 | 変更後 |
|---|---|---|
| リポジトリの親フォルダ | `smartTaskManagement` | `Avoliq` |
| アプリ表示名・ウィンドウ名・HTMLタイトル | `smartTask` | `Avoliq` |
| npm パッケージ名 | `smart-task` | `avoliq` |
| Cargo パッケージ・ライブラリ名 | `smart-task` / `smart_task_lib` | `avoliq` / `avoliq_lib` |
| Tauri識別子 | `com.kei06.smarttask` | `com.kei06.avoliq` |
| アプリデータ保存先 | `~/Library/Application Support/smartTask/smart-task.db` | `~/Library/Application Support/Avoliq/avoliq.db` |
| 検索欄のDOM ID・パネル型名 | `smarttask-*` / `SmartTaskPanel` | `avoliq-*` / `AvoliqPanel` |

### データ互換性

- 旧アプリのデータベースは自動移行しない。
- `Avoliq` は旧 `smartTask` と別アプリとして起動し、初回は新しい空のデータベースを作成する。
- 旧データの削除・変更は行わない。手動移行機能も今回の対象外とする。
- この方針により、既存の配布済みアプリのアップデート経路とデータを変換する責務は負わない。

### アイコン

- ブランドの正式な元画像 `design/avoliq-app-icon.png` を唯一の入力として使う。
- Tauri が参照する `src-tauri/icons/` の macOS・Windows・汎用PNGアイコンを、この元画像から全サイズ生成して置き換える。
- `design/avoliq-logo.png` はブランド資産として維持するが、既存のタスク操作UIへロゴ表示を新設しない。

## 8. 受け入れ基準

- アイコンは小さい表示でもチェックが一読できる
- ガラスの表現は一つのマークに集約され、過剰な半透明装飾がない
- ロゴの表記は正確に `Avoliq` となっている
- アイコン、ロゴ、LPのコンセプトは「直感的に、自然に思考を整え、次へ進める」と矛盾しない
- 操作キーやキーキャップはブランドの主ビジュアルに含まれない
- アプリの表示名、バンドル名、HTMLタイトル、npm/Cargoパッケージ名、Rust内部名に `smartTask` / `smart-task` が残らない
- Tauri識別子が `com.kei06.avoliq` であり、データベースは `~/Library/Application Support/Avoliq/avoliq.db` を使う
- `src-tauri/icons/` のTauri設定に列挙されたアイコンがすべて存在し、`design/avoliq-app-icon.png` に由来する
- 旧 `smartTask` のアプリデータを読み書き・削除しない
- 対象ユニットテスト、型検査、フロントエンドビルドが成功する
